# agentworks

`OptimusFoundry/agentworks`: Go API (`base-server/`) and Vite SPA (`webapp/`),
served at `agentworks.protoapp.xyz`. Prototype tier. Modeled on
`products/aitravel/` — same base-server lineage, same shape.

## What does not work yet

This stack runs **the API process only**. agentworks' runner lives in that
process but shells out to `orca` (plus a long-lived `orca serve`), `claude`
(with bubblewrap), `git` and two helper binaries, on a persistent disk
(`AGENTWORKS_DATA_DIR`, repo mirrors, worktrees). The app's own docs target a
single systemd host (`docs/ARCHITECTURE.md` "Single host",
`base-server/docs/HOST.md`). The stock `base-server/Dockerfile` is alpine plus
the server binary, so:

- sign-in (email and Google), the webapp and plain API calls work;
- **agent runs fail.** Fixing that is a choice between a runner-capable image
  with a host bind-mount on the shared ECS host, or a dedicated EC2 host —
  not made yet.

Also not routed: inbound hooks are `POST /hooks/:project_id/:name` at the
root, and `modules/product` forwards only `/api/*` to the ALB. GitHub App and
Slack are unconfigured (the server enables each only when its credentials are
set).

## What this stack owns

| Resource | Name |
|---|---|
| Webapp bucket + CloudFront | `protoapp-agentworks-webapp` (module convention) |
| API service | ECS `agentworks-api`, ECR `agentworks-server`, target group `agentworks-api-tg` |
| Migrator | task definition `agentworks-migrator` (no service), ECR `agentworks-migrator` |
| Logs | `/agentworks/api` — stream prefixes `api` and `migrator` |
| Media bucket | `protoapp-agentworks-media` (**private**) + IAM user of the same name |
| KMS | `alias/agentworks-secrets` (`prevent_destroy`) + task role `agentworks-api-task` |
| SSM | `/agentworks/*`, plus the deploy manifest `/agentworks/manifest` |
| ALB rule priority | **320** (sjocamp 100, meerkat 200, orca 300, aitravel 310) |
| Terraform state | `s3://agentworks-terraform-state` |

## Google OAuth

The client is real (not a placeholder, unlike aitravel). Its authorized
redirect URIs in Google Cloud Console must include

    https://agentworks.protoapp.xyz/api/auth/google/callback

which is what `/agentworks/auth/google_redirect_uri` holds and the task gets
as `AUTH_GOOGLE_REDIRECT_URI`. The webapp build needs the same value as
`VITE_GOOGLE_REDIRECT_URL`, plus `VITE_GOOGLE_CLIENT_ID`.

## Secrets

Account-wide values come from `/platform/*` through `data.tf`: resend, stripe
secret key, RDS host/port.

Per-product values come from the gitignored `secrets.auto.tfvars`, rendered
from env-registry (`values/agentworks.enc.env` must exist first):

```bash
make secrets PRODUCT=agentworks
make check-secrets PRODUCT=agentworks
```

| Value | State |
|---|---|
| `auth_jwt_secret` | Generate fresh (`openssl rand -base64 48`); never copy a sibling's |
| `gateway_token_key` | Generate fresh. Boot fails without it in production |
| `auth_google_oauth_client_id` / `_secret` | The agentworks Google client |
| `payments_stripe_webhook_secret`, `email_resend_webhook_secret` | Placeholders until those webhooks are registered |
| `email_sender_address` | `no-reply@protoapp.xyz`, already Resend-verified |

`SECRETS_KMS_KEY_ID` is the stack's own KMS key. Everything reaches the
container as plain `environment`, as in every other product.

## Kafka

On the shared broker, `EVENTS_TOPIC` / `EVENTS_CONSUMER_GROUP` are set to
`agentworks.webhook-events` / `agentworks.webhook-consumers` (the server's
defaults are unprefixed). `agentworks.inbound`, `.platform` and `.transcript`
are created at boot with `KAFKA_PARTITIONS` = 3. `resend.email.events.v1` is
hardcoded in the server and shared with any other product that uses the
default.

## Database

As aitravel: role `agentworks_app` owning database `agentworks`, password
generated by Terraform (`/agentworks/db/password`), role and database created
by hand after the first apply. Follow `products/aitravel/README.md`
§ Database with `aitravel` → `agentworks`.

## Deploys

The app repo's `agentworks-server.yml` and `agentworks-webapp.yml` deploy on
push to `main`, with the same stages as every other product: tests →
build-push (API + migrator) → migrate → deploy-ecs, and lint → build → S3 →
CloudFront invalidation. Both read every identifier from
`/agentworks/manifest`. The org-wide `repo:OptimusFoundry@167594521/*` OIDC
subject in `platform/variables.tf` lets them assume `github-actions-admin-aws`.

Both ECS task definitions point at `:latest`. Until the first image push,
`agentworks-api` keeps failing to pull — expected.

## Bootstrap checklist

1. Add `values/agentworks.enc.env` to env-registry; `make secrets PRODUCT=agentworks`;
   put `cloudflare_email` in `terraform.tfvars`.
2. `aws s3 mb s3://agentworks-terraform-state`, then
   `terraform -chdir=products/agentworks init`, plan to a file, read it, apply that file.
3. Create the role and database (§ Database).
4. Add the redirect URI to the Google client (§ Google OAuth).
5. Push to `main` in the app repo (or dispatch both deploy workflows).

### Smoke test

`/health` is at the root, so it is reachable only by the ALB health check, not
through CloudFront. From outside, an unauthenticated protected route answering
401 (not CloudFront's 404/502) proves the path CloudFront → ALB → task:

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://agentworks.protoapp.xyz/api/protected/user   # 401
aws logs tail /agentworks/api --region us-east-1 --since 15m
```
